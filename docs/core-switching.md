# dae / sing-box / mihomo 内核切换

从 NaiLink 0.6.34 起，可在面板顶部点击“内核”。默认仍是 dae，升级不会自动换内核。

0.6.45 重新整理了窗口：打开时选中正在使用的内核，运行状态和目标选择分开显示。按“选择内核 → 检查兼容性 → 切换”操作；行为差异、扩展组件和资源说明可展开查看，底部操作栏在手机上也保持可见。

1. 选择 sing-box，点击“下载并安装”。下载或校验失败不停止当前代理，可重试。
2. 选择“非 TUN · TPROXY”或“TUN · 备用”，再点击“检查兼容性”。缺少模块时可点击“安装接管依赖”，完成后重新检查；修改配置或模式后也需重新检查。未应用的编辑不会被顺带应用。
3. 检查通过后切换。切换会短暂断连，请等待结果，不要断电。关闭窗口不会取消后台任务。
4. 想切回时选择 dae，重新检查，再切换。

窗口内的“常驻内存”读取管理服务及当前内核的 RSS，按需刷新，关闭窗口后停止轮询。dae 内嵌在管理服务中；sing-box / mihomo 只有选中的一个运行。安装另两个程序会占用存储和可回收文件缓存，不代表三个内核同时使用运行内存。RSS 合计可能重复计算共享页，是近似值；开启 Tor 时不显示缺少 Tor 子进程的不完整合计。

本版补齐 dae 关闭后的全局代引用清理，并在原生内核重载或回退后直接持有当前会话，释放旧包装对象及其 DNS 匹配器、统计等引用。保留已有限次重试、单内核接管、实际 DNS / 连接就绪检查和失败回退；不会为了减少显示值而清空系统缓存或改写用户配置。

针对切回 dae 后客户端仍保留旧 DNS 地址的情况，域名拨号模式会为首次域名验证最多等待 250 毫秒，验证成功后首个连接即可使用域名。沿用现有引导 DNS 与验证结果，不信任未经验证的 SNI；直连规则、按 IP 拨号与其他拨号模式保持。最多同时等待 64 个请求、执行 16 个首次验证；超出容量或未能及时验证时，继续原 IP 行为。调试日志中的 `first_domain_validation` 只记录阶段、耗时和固定结果分类，不记录凭据。

0.6.36 修复手动/订阅节点测试时对 SS `type=tcp`、HY2 `security=tls`、Reality 混合密钥协商提示和 VMess 导出元数据的兼容。VMess 的 `verify_cert` 会转换为对应证书校验设置；与其他选项矛盾时拒绝，不自动放宽验证。HY2 的有效 Base64 ECH 配置会保留到原生 TLS；公开域名为空或格式异常时明确提示，不静默删除 ECH。

节点结果中的“参数不兼容 / ECH 配置异常”发生在测试发起前；“超时”表示连接未在期限内完成。订阅内的流量、到期日期、官网等提示项应与真实可连接节点区分，不能据此判断整个协议不可用。兼容性检查只覆盖当前运行配置；订阅列表里的其他节点会在各自测试时检查。

0.6.35 补齐 `headerType=none`、VLESS/Trojan 的 `udp` 开关与 Reality `spx` 参数处理。检查会列出当前运行配置中每个不兼容节点的名称和中文原因，附加参数仅显示名称，不输出密码或完整链接。`spx` 对应 Xray 验证失败后的爬虫路径，sing-box 不执行此行为；原链接保留，报告会说明差异。配置检查不代表机场线路一定可用，实际切换仍需通过 DNS 和连接检查。

本版同时支持当前规则引用的外部 GeoIP/GeoSite `.dat` 文件，不删除 AdZero 等插件加入的规则；外部规则变化后需要重新检查。较大的规则库使用有界的独立原生配置检查时间，超时与配置错误分别提示。

按域名拨号模式会在代理规则匹配后使用嗅探到的有效域名，减少旧 DNS 地址造成的连接失败；直连规则和按 IP 拨号保持原行为。尚不能等价转换的高级拨号模式会明确阻止切换，不自动改为其他模式。

## 支持范围

| 项目     | 范围                                                                                       |
| -------- | ------------------------------------------------------------------------------------------ |
| 架构     | sing-box / mihomo：x86_64、ARM64；ARMv7/MIPS 保持原 dae 支持限制                           |
| 安装前提 | 已能安装 NaiLink；原安装器仍检查 dae 的 eBPF/BTF 条件，不是绕过旧内核限制的新安装途径      |
| 接管方式 | dae 使用 eBPF；sing-box / mihomo 可选 TPROXY 或 TUN，接入 nftables / firewall4             |
| 资源     | 安装可选内核需要额外 180 MiB 可用存储，建议路由器有 1 GiB 以上内存                         |
| 常见节点 | SS/SS2022、VMess AEAD、VLESS、Trojan、HY2、AnyTLS、TUIC v5、SOCKS、HTTP/HTTPS 的已适配参数 |
| 规则库   | 读取现有 GeoIP/GeoSite `.dat` 中引用的条目，生成 sing-box 原生规则，不覆盖原文件           |

0.6.38 起支持 Hysteria 1、SSH、Snell 4/6，以及 sing-box 单个出站 JSON 和封闭出站组合（包括 ShadowTLS）。原生 JSON 节点仅供 sing-box 使用；若当前运行配置引用它，切回 dae 前会明确阻止并列出节点，原配置保留。SSR、Juicity 不由 sing-box 实现；0.6.39 起提供按需安装的 Naive/Cronet、WireGuard 和私有 Tor 扩展包。部分高级参数仍会阻止切换，不承诺兼容所有协议。多 WAN、固定群组包含多个节点、自定义策略参数、MAC 分流和部分高级 DNS 规则也暂不转换。兼容性报告以实际运行配置为准，节点和原始配置一直保留。

自动选择映射为 sing-box URL 测试策略，平滑算法与 dae 不完全相同；节点域名引导解析使用首个直连 DNS 上游，其余上游经默认群组。切换会清空原内核的运行缓存，可能改变自动选择的出口，已有浏览器连接不能无缝迁移。AI 服务是否接受出口还取决于节点 IP 和网站策略。

## Mihomo（0.6.40 新增）

在“代理内核”窗口选择 **mihomo**，按需安装固定版本 **1.19.33**，检查兼容性后切换。只运行所选内核，下载、校验失败不停止当前代理；切换失败会尝试恢复之前可用的内核。原始节点、订阅、配置和未应用的修改一直保留。

- **架构与资源**：x86_64、ARM64，下载约 20–22 MiB，安装预检要求额外 180 MiB 可用空间。ARMv7 / MIPS 暂不提供 Mihomo，原 dae 安装限制不变。
- **已适配**：SS / SS2022、SSR、VMess AEAD、VLESS / REALITY、Trojan、Hysteria 1 / 2、AnyTLS、TUIC v5、SOCKS5、HTTP / HTTPS、SSH、WireGuard、Snell 4 的已映射参数。SSR、Snell 4 尚无独立服务端实机互通证据；Naive、Tor、Juicity、ShadowTLS 和未映射的高级参数会明确阻止切换，不会静默删除。
- **配置方式**：继续使用现有分享链接或受限的单出站 JSON。不会导入完整 Clash YAML，不替换数据库，也不会安装另一套系统服务。支持范围以窗口的兼容性报告为准。
- **DNS 与分流**：保留现有 DNS 请求规则的顺序、GeoSite、查询类型、UDP / TCP / TLS / HTTPS 传输和代理路径，使用本机私有 DNS 桥接；代理 DNS 失败不会偷偷直连。节点域名用首个直连上游引导，IPv4 / IPv6 由现有配置控制。尚未适配的响应规则会阻止切换。
- **策略差异**：平滑 / 平均低延迟映射为原生 URL 测试，算法与 dae 不同。固定多节点群组、多 WAN、MAC 分流等暂不转换；实际检查通过才允许切换。日志中的 `nk-…` 是防止规则注入的内部标识，原节点名称保留在面板。
- **测试方式**：普通节点整批共用私有进程，最多 8 个 HTTP 请求并行；WireGuard 小批测试，默认 1 个工作线程。启动时间不算节点延迟，结果标记来源，切换会清理旧内核测试缓存。

上游文档列出的全部协议不代表此适配层已支持。切换会短暂断连，旧浏览器连接不能迁移，网站也可能因出口 IP 变化重新验证。

## 接管方式

0.6.58 起，sing-box、mihomo 可选非 TUN 接管；dae 仍使用 eBPF。老安装继续沿用原模式，不会因升级而自动改变流量路径。

首次安装仍默认运行 dae；首次选择外置内核时预选非 TUN。已有 sing-box / mihomo 的 TUN 配置继续保留，需要时再手动切换。

| 模式            | 流量路径                                                                | 前提                                              |
| --------------- | ----------------------------------------------------------------------- | ------------------------------------------------- |
| 非 TUN · TPROXY | 所选 LAN → 独立 nftables 规则与策略路由 → 当前内核 → 原有分流规则与节点 | firewall4、nftables、匹配固件的 `kmod-nft-tproxy` |
| TUN · 备用      | 所选 LAN → 虚拟网卡 `nailink0` → 当前内核 → 原有分流规则与节点          | `kmod-tun`、nftables / firewall4                  |

两种方式都接管 TCP / UDP，并支持 IPv4 / IPv6。路由器自身的普通 TCP / UDP 连接也会接管；内核自身的出站、局域网及管理地址跳过接管，防止循环。DNS 53 端口交给当前内核处理，继续使用原有 DNS 分流，不改成第三方 DNS。内核管理接口仍只监听本机并带认证；DNS 与透明监听口有独立防火墙保护。

非 TUN 使用独立规则表、路由表和所有权记录，退出时只清理自己创建的资源，不清空其他插件规则。WAN 地址变化会刷新本机地址例外；内核退出后尝试恢复当前内核和模式。切换前检查实际配置和系统规则能力，成功就绪后才保存新选择；失败尝试回到原内核、原模式。切换仍会短暂断连，旧连接不能无缝迁移。

Docker 等服务开启 LAN 桥接过滤时，会检查并使用独立的桥接适配表，只处理发往路由器 MAC 的公网 TCP/UDP。需要固件的 nftables broute 能力和匹配的 `kmod-nft-bridge`；“安装接管依赖”会一并准备。不会关闭 Docker 的桥接过滤，也不修改其规则。这个适配同时纳入切换、退出、地址/桥接拓扑变化和失败恢复的资源管理。

**限制：**仍限已支持的 x86_64 / ARM64，不绕过安装器的 eBPF/BTF 检查；不接管其他正在运行的透明代理，也不改造旧 fw3 防火墙。桥接过滤与 VLAN 或严格反向路径检查组合暂需使用 TUN，检查会给出原因；不会通过放宽系统安全设置来启用。Tor 子进程暂需选择 TUN，非 TUN 检查会阻止这类配置；节点原文保留。依赖安装失败或要求替换现有系统包时停止，现有模式继续运行。

非 TUN 不是测速加速开关，实际速度仍取决于节点、线路和设备；请选择实测稳定的模式。可随时在同一窗口重新检查并切回 TUN。

## 添加 sing-box 原生节点

导入窗口显示当前内核支持的协议，点击名称查看格式；手机也可点按查看。普通分享链接继续使用原有方式；Hysteria 1、SSH、Snell 可使用对应 URI。更多原生选项可粘贴单个出站 JSON，例如：

```json
{
  "type": "ssh",
  "tag": "我的 SSH",
  "server": "example.com",
  "server_port": 22,
  "user": "用户名",
  "password": "密码",
  "host_key": ["服务器提供的完整公钥"]
}
```

生产 SSH 节点应配置服务器公钥，避免只靠密码识别服务端。JSON 只允许代理出站，不接收完整系统配置、文件路径、命令或指向组合外部的 detour。证书、私钥可使用内联内容。组合格式为 `{"tag":"主出站标签","outbounds":[...]}`，最多 16 个内部出站；ShadowTLS 必须与内层代理组成封闭组合。编辑时保留完整 JSON，原有节点不自动转换。

支持范围按[固定版本注册表](https://github.com/SagerNet/sing-box/blob/v1.14.3/include/registry.go)和实际构建组件检查；[原生文档](https://sing-box.sagernet.org/configuration/outbound/)列出的其他版本功能不等于当前包已具备。

## Naive、WireGuard 和 Tor

NaiLink **0.6.39 起**，先保持 dae，在“代理内核”窗口选择 sing-box，点击“按需安装扩展协议包”。下载及校验完成后再检查兼容性、切换。安装失败可重试，现有节点和配置不变。普通节点继续使用轻量内核；只有运行配置或测试包含扩展协议时，才使用扩展程序。Naive / WireGuard 手动测试每批最多 8 个节点，普通协议仍整批共用进程。组合只启动主节点实际引用的链条，未使用条目保留在原始 JSON 中。

扩展包基于 `1.14.3-nailink.2`，限 **x86_64 / ARM64**，压缩约 30 MiB，安装预检要求额外 400 MiB 可用存储。建议至少 1 GiB 内存，使用 Tor 建议 2 GiB 以上。ARMv7、MIPS 暂不提供，也不能绕过原安装器的内核检查。以下数值是默认设置，不是进程内存上限。

| 协议        | 导入方式                                                                                      | 使用限制与资源                                                                                                                                     |
| ----------- | --------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| Naive HTTPS | `naive+https://用户名:密码@服务器:端口#名称` 或原生 JSON                                      | Cronet TLS，必须验证证书；可内联 CA，不支持 `insecure`。默认接收窗口 8 MiB，并发参数最多 4。UDP 需服务端及节点显式启用 UDP over TCP。              |
| WireGuard   | `wireguard://私钥@服务器:端口?publickey=公钥&address=10.0.0.2%2F32#名称` 或现代 endpoint JSON | 用户态 `system:false`，默认 1 个工作线程，最多 4；不创建宿主网卡、不开放监听。需有效密钥、本地地址和对端网段。                                     |
| Tor         | `tor://default#Tor` 或原生 JSON                                                               | 仅 TCP，不支持 UDP/QUIC。每个运行配置最多启用 1 个；手动测试串行引导，最多等待 180 秒，普通节点先显示结果。首次引导较慢，线路需要能访问 Tor 网络。 |

WireGuard 的完整 JSON 示例（将占位密钥替换为服务端提供的 32 字节 Base64 值）：

```json
{
  "type": "wireguard",
  "tag": "我的 WireGuard",
  "system": false,
  "address": ["10.0.0.2/32"],
  "private_key": "你的私钥",
  "peers": [
    {
      "address": "example.com",
      "port": 51820,
      "public_key": "服务端公钥",
      "allowed_ips": ["0.0.0.0/0", "::/0"]
    }
  ]
}
```

封闭组合可以包含 `outbounds` 与 `endpoints`，主节点由顶层 `tag` 选择，最多 16 个内部节点；引用外部节点、循环、系统网卡、文件路径和命令均拒绝。Tor 可在组合内经另一个代理 `detour` 连接，但不会自动替你选择线路或绕过服务端限制。

Tor 的程序、musl 加载器和依赖库位于 NaiLink 私有组件目录，不替换系统库、不安装上游 Tor 服务。仅使用时运行；主代理和临时测试分别保存引导缓存，避免数据目录锁冲突。Tor 队列预算设为 64 MiB，但共识、连接和其他内存仍另计。切换、停止或内核崩溃时会终止子进程；缓存保留在 `/etc/daed/tor`，随配置备份。卸载前照常备份，然后清理组件及缓存。

扩展安装采用完整下载、固定 SHA256、ELF / 版本 / Tor 私有依赖校验与目录指针原子替换。旧组件保留用于恢复；不覆盖数据库、节点、订阅和未应用编辑。升级 NaiLink 不自动启用这些协议。

## 如何比较节点延迟

0.6.37 起，dae 与 sing-box 的手动测试（0.6.40 扩展至 mihomo）使用同一配置中的 URL、HTTP 方法和已解析的 IPv4 / IPv6 目标，取先成功的请求。数值包含新建连接、协议握手和 HTTP 响应，并非 Ping；可选内核私有测试进程的启动时间不计入。

路由模式将整批测试交给后台任务，原生内核共用私有进程，最多 8 个 HTTP 请求并行；0.6.43 起三内核普通节点的手动 HTTP 尝试期限统一为 8 秒。结果逐条显示，停止保留完成项，剩余项可以继续；切换内核取消旧任务。临时请求失败不会自动重复启动同一任务。

页面保留手动测试结果及时间，不再被后来的后台检测替换。修改节点连接参数后，旧结果失效，需要重新测试。未手动测试的节点可显示带“自动”标记的后台结果：它可能复用连接，不能拿来直接对比首次连接。各内核的协议实现、后台选择算法和线路波动仍可能造成差异，不保证换内核后数值相同。

## 失败后怎么办

目标内核配置不通过时不切换。启动或连接检查失败时，先撤销目标资源，再尝试恢复原内核和运行配置；节点、订阅、群组及待生效编辑不会删除。刷新后重新打开“内核”可查看结果，运行日志和 `nailink --check-network` 也会显示当前内核。

回退也失败、磁盘异常或无法确认资源归属时，面板会明确提示。不要反复切换或卸载；先保留 `/root/daed-backups` 与现有配置，再检查日志。内核意外退出仅有限次自动重启，避免持续重启占用资源。

可选程序固定为 **1.14.3-nailink.1 兼容构建**，基于 [sing-box 1.14.3 源码](https://github.com/SagerNet/sing-box/tree/v1.14.3)，修复本次真机复现的 Reality 密钥份额处理问题。保留指纹、SNI、公钥、短 ID 与认证校验，未放宽安全验证。[构建方法和补丁范围](../openwrt/singbox.md)可审查，静态程序及对应源码随 NaiLink 发布，下载仍核对固定 SHA256、架构与版本。

已装过官方 1.14.3 的用户，升级 NaiLink 后先保持 dae，在“内核”窗口检查兼容性，按提示重新安装可选内核，再检查和切换。此操作不删除节点、订阅或原配置。发布包不自动启动第二套代理服务。Mihomo 已在 0.6.40 接入，0.6.42 起支持从 Clash YAML / JSON 提取内嵌节点；完整配置中的 DNS、路由和监听不会导入。
