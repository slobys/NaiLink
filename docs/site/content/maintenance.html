切换 dae / sing-box / mihomo

点击顶部内核，选择目标和接管方式，安装组件、检查兼容性后再确认切换。sing-box、mihomo 可选非 TUN（TPROXY）或 TUN；依赖按所选模式检查，限 x86_64 / ARM64。

升级保留当前内核、模式和配置，切换保留未应用编辑。操作期间可能短暂断连，失败尝试恢复原选择，关闭窗口不会取消后台任务。完整步骤与流量路径见内核与接管方式。

v$version 更新与验证范围

当前发布为v$version 测试版。这轮更新保留原协议参数、DNS 上游、路由和接管方式：

  • 应用并发保护：读取一致快照后释放数据库事务，再等待内核重载，避免同时移除群组节点阻塞页面。运行状态记录本次实际加载版本，之后的编辑保留为待应用，已删除群组不会重新创建。
  • DNS 连接恢复：DNS 桥的 TCP / TLS 复用连接迟迟不返回时，符合条件的只读查询在原期限内最多发起一次同上游、同出口的备用请求；保留慢但有效的原响应，未使用的连接及时释放。
  • 启动与清理：三内核管理、原生重载和私有节点测试共用就绪检查，拒绝已经超时或取消的成功结果；失败清理使用独立的 30 秒时限。
  • 已有恢复能力：非 TUN 检查并补回自己的缺失策略路由，内核意外退出时尝试恢复当前内核与模式；与其他服务冲突时明确停止并提示。

本版发布检查包含多架构构建、安装与回退、双栈转发和桥接。ARM64 实机完成三个内核、两种外置接管模式往返及短时公网传输。电脑与手机触控模拟已检查；这些结果不等同于所有设备长期稳定、实体手机验证或持续视频带宽保证。查看验证记录。

旧版本请先用 SSH 菜单或下面的固定版本命令升级一次，之后才会显示版本按钮。更新需要路由器能访问 GitHub；下载、校验或环境检查失败时，原服务和数据不会被替换。断电或服务故障后可重新打开版本窗口查看结果；失败原因不明确时，先检查运行日志，避免重复执行。

0.6.50 起，下载重试共用文件时限，并优先复用本次已成功的官方入口。在线安装准备最多 15 分钟，超时先退出， 保持原代理运行，为后续安装和失败恢复留出时间。APK 依赖已安装或已缓存时无需刷新固件软件源；缺依赖时才走原固件软件源。 面板会区分软件源失败、依赖不满足与准备超时。手动升级后，旧任务记录仍保留，但会结合当前版本显示，不再误报本次安装失败。

SSH 菜单仍然可用：

0.6.33 起，在线更新在停服前额外下载并校验当前版本的回退安装包；无法取得回退包时，原服务继续运行。备份失败会恢复旧服务，安装失败或管理 HTTP 未就绪会尝试恢复旧包和配置快照。升级期间请等待维护任务结束再编辑配置。

  1. 先到发布页查看版本说明及兼容性。

旧版菜单遇到 raw.githubusercontent.com 解析失败时，这个固定版本入口也可绕过旧 Raw 下载入口。若 github.com 也不能访问，先修复路由器自身 DNS 或网络，参见下载失败。

GeoIP / GeoSite 规则库有什么用

打开“更新规则”窗口会检查上游批次，显示是否有新版本、上游批次及检查时间。五分钟内复用结果，也可点重新检查按钮。检查只读取发布信息，不下载或替换规则，不中断代理；检查失败会显示“暂时无法确认”，当前规则保留。

“批次已是最新”表示批次一致；点击“更新”仍会重新校验本地文件。自定义规则或没有批次记录的系统规则不会被误报为最新。明确点击窗口里的“更新”后，才开始下载、校验和加载。

它们是分流用的“分类字典”，配合高级设置中的路由和 DNS 使用。

  • GeoIP：判断 IP 属于哪个地区，或是否为局域网地址。例如 geoip:cn 可用于国内 IP 直连。
  • GeoSite：判断域名属于哪类网站。例如 geosite:cn 可用于国内网站直连，或选择国内 DNS 解析。

默认方案已引用这两类数据。只有路由或 DNS 引用的分类才会生效；更新规则库不会替你改分流策略，AI 网站走哪个群组仍由路由设置决定。

在任意菜单顶部点击更新规则（版本号与内核之间），先查看当前批次与两类数据的用途，可展开详细说明查看来源、内核和更新说明，再点击窗口里的更新。 打开窗口不会自动更新。进度与错误保持可见；关闭窗口后后台任务仍会继续，可再次打开查看。

dae 直接读取规则文件；sing-box、mihomo 使用同一份数据转换后的规则。两份文件先下载、校验，再一起加载；失败恢复旧版，保留节点、配置和未应用的编辑。数据保存在 NaiLink 独立目录，不覆盖其他插件或用户自定义规则文件。

更新后如何判断代理已恢复

0.6.30 起，更新脚本分别检查管理页面、代理监听、DNS 上游初始化和缓存路由恢复。网络仍在恢复时会提示状态并保持服务运行，保留节点和配置。SSH 执行下面的只读检查可查看详情： 

nailink --check-network

诊断会显示群组策略和 IPv4 / IPv6 候选节点，并对 Google、ChatGPT 发出有时间限制的请求。候选节点不是网站实际看到的公网出口 IP；自动选择可能在重启后选中不同节点。网站的 VPN 提示还可能取决于出口信誉、账户和会话，不能通过代理就绪状态判断。

dae 正常停止时，最多 1024 条、2 MiB 的仍有效 DNS 地址记录保存在 /var/run/daed，仅在配置匹配、快照不超过 10 分钟且原 TTL 未过期时恢复，按当前规则重建分流关联。不会延长 DNS TTL 或改动配置。该目录为易失存储，重启路由器后会消失。

首次从 0.6.29 或更早版本升级没有旧快照可用。新版本之后的正常服务停止、重启和升级才会使用该机制；不能保证断电、强制杀进程后恢复。升级会关闭原进程的连接，新请求仍需要重新建立连接。

sing-box、mihomo 使用各自的运行缓存，不接收 dae 的已有答案缓存。切换会定向回收 NaiLink 原有 DNS 接管映射，让设备的原 DNS 会话可以重新解析；这不会迁移已经建立的网站连接。

备份在哪里，包含什么

备份保存在 /root/daed-backups。安装器会先停止服务并等待退出，再归档配置、数据库及 WAL，以避免复制正在写入的数据。 

ls -lh /root/daed-backups

请把需要长期保留的归档另存到可信设备。备份可能包含节点密码、订阅令牌和账户信息，不要公开上传。目录权限为 0700，归档权限为 0600。

保留报错与备份，再判断是否需要恢复

面板更新及 --update-only 在停服前准备回退包，安装失败会尝试恢复旧包和原配置；普通安装菜单不等同于这一事务保护。 下载或兼容性检查失败不会替换现有程序。若页面明确提示回退失败，请保留报错和备份路径，确认软件包状态后修复，不要清空重装。

需要恢复备份时怎么办？

目前菜单没有“一键恢复备份”选项。先停止 NaiLink，保留当前目录的另一份副本，核对归档内的路径、原版本和数据库状态，再由熟悉该固件的人恢复。不要直接向运行中的数据库覆盖文件，也不要把另一台路由器的接口配置整体覆盖进来。

卸载：先备份，再清理

  1. 运行 nailink，选择 2 卸载。
  2. 阅读提示，输入 y 确认。
  3. 卸载会先停止服务并创建备份，再清理插件及当前节点、订阅、群组与配置。
  4. 保留的备份仍在 /root/daed-backups；共享依赖和已有 BTF 不会因此一并删除。

卸载可以离线执行。旧版或需要直接使用命令时：

daed-router-setup --uninstall

上面这条直接命令不经过菜单确认，执行前请确认确实要删除插件与当前数据。正常更新不要使用它。

什么时候才用清空重装

--reinstall 用于明确需要清空旧配置或替换其他来源的 Daed 包的情况，会先备份再清理，但不会自动导入备份。原节点和规则需要重新配置，不能把它当普通升级方式。

新旧品牌沿用 daed 服务、daed-router / luci-app-daed-router 包名和 /etc/daed 目录，所以系统里看到旧名称属于预期，不代表品牌更新失败。

0.6.41 起，大组件下载最多允许 10 分钟；连接与响应头仍有短超时，文件大小和校验不放宽。下载失败保留现有代理及程序，可重新尝试。
