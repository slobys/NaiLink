先检查这些条件

  • 系统：OpenWrt、ImmortalWrt、iStoreOS，具备现代 JavaScript LuCI。
  • 内核：Linux 5.17+，具备核心需要的 eBPF/JIT 功能和可用 BTF。版本号达到要求，不等于功能全部具备。
  • 软件源：能提供与当前内核 ABI 匹配的模块、证书和规则库。不要混用其他固件的软件源。
  • 空间：v$version 的运行程序本体约 52–57 MiB，另需规则库、依赖、下载、解压和备份空间。16/32 MiB 闪存设备通常不适合直接安装；脚本不会扩容。
  • 权限与网络：能够以 root 登录路由器 SSH，路由器自身可以解析并访问 GitHub。

本项目尚未给出覆盖所有设备的最低内存或吞吐保证。节点规模、规则数量、并发连接和协议都会影响资源占用，不宜只按 CPU 型号判断性能。

CPU 架构支持范围

架构 当前状态
x86_64 提供安装包；采用 amd64 v1 基线，仍需通过内核检查。
ARM64 / aarch64 提供安装包；采用 ARMv8.0 基线，按固件 ABI 匹配。
ARMv7 小端 仅实验构建，不推荐用于透明代理。已测常见内核缺少必需的 BPF 回调能力。
MIPS32r2 / MIPSel32r2 仅实验构建，不推荐用于透明代理。区分大小端；已测常见内核同样不能加载所需回调。
ARMv5/v6、MIPS64、RISC-V、32 位 x86 暂不提供安装包。
32 位实验构建暂不推荐安装作为透明代理使用

OpenWrt 24.10.4 / Linux 6.6.110 的 ARMv7、MIPS 大端和小端在完整系统测试中均未通过 bpf_loop 回调加载。页面能打开、数据库能读写，均不能证明透明代理正常。自定义内核通过最小探针后，仍需要完整网络验证，不要绕过检查强装。

通过中文菜单安装

用 SSH 以 root 登录路由器，执行下面的一行命令打开菜单。

nl=$$(uclient-fetch -O- ${url}install.sh) && sh -c "$${nl:?下载为空}" -- --menu

选择 1 安装 / 更新 后，脚本自动查找最新公开的 NaiLink 版本（包含测试版），无需填写版本号。

  1. 等待环境检查、依赖安装与包校验完成。不要同时执行第二次安装。
  2. 安装成功后刷新路由器后台，进入 服务 → NaiLink。
  3. 继续阅读首次设置，导入节点并应用配置。

菜单还提供 2 卸载、3 检查环境 和 0 退出。安装后运行 nailink 可再次打开菜单。

安装器结合 CPU、包管理器架构与 IPK/APK 格式选择安装包，并核验下载内容。内核检查会临时加载并关闭未挂载到网卡的探针；不会为通过检查而更改 JIT、DNS、路由或防火墙。

只检查环境，暂不安装

打开菜单后选择 3 检查环境。已安装用户可直接运行 nailink 打开菜单。

环境检查不安装软件包或修改软件源。若需预演下载、校验和依赖检查，可将命令末尾的 --menu 换成 --dry-run。APK 依赖预演使用本机已有索引。

手动下载与源码

当前测试版发布页提供 IPK / APK v3、校验清单和完整源码。优先使用安装脚本，以免手动漏装依赖或选错 ABI。APK 需要 apk-tools 3.x；不要使用强制忽略依赖或内核 ABI 的参数。

安装失败先看安装故障排查。旧版已有配置时无需先卸载，详见保留数据更新。
