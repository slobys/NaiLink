# NaiLink · 奶油互联

支持 OpenWrt、ImmortalWrt、iStoreOS 的现代 LuCI，提供 x86_64 / ARM64 及试验性 ARMv7 / MIPS32 / MIPSel32 的
IPK 和 APK v3 安装包。当前测试版：[openwrt-v0.6.62](https://github.com/slobys/NaiLink/releases/tag/openwrt-v0.6.62)。

本项目从 0.6.14 起更名为 NaiLink（奶油互联），侧边栏显示 **NaiLink**。0.6.13 及更早版本显示 **Daed**。沿用原有包名、服务、路径和配置，可继续保留数据升级。

## 0.6.62 大连接列表统计

sing-box / mihomo 的连接接口返回完整明细。运行概况改为逐条汇总，不保存完整连接数组；仅此统计端点使用 16 MiB 响应上限，其他接口维持 2 MiB 限制，均保留两秒期限。畸形数据、截断和超限仍会报错，不伪造新的零流量样本。

多页面共享采样，普通连接数每秒一次，达到 2048 / 8192 条时分别每 2 / 4 秒一次；失败后至少间隔一秒重试，诊断日志至多每 30 秒一次。统计错误由运行概况显示，恢复后自动消除提示，操作失败仍正常提示；不更改节点、分流、接管方式或依赖。

## 0.6.61 应用配置并发保护

应用使用短事务读取一致快照，释放数据库连接后才等待内核，再用短事务保存实际加载版本。并发移除节点不会与重载互相等待，后续编辑保持待应用；记录运行群组仅关联仍存在的行，不重建已删除群组。应用期间界面暂时禁用成员移除和拖动，完成后恢复。

请求在排队前取消不会触发重载；已接收的操作使用独立、有界的完成时限，浏览器关闭后仍确认状态。回调缓冲防止迟到回复阻塞内核管理循环，不更改节点、协议、DNS 或接管方式。

## 0.6.60 首次连接与切换保护

- 共用 DNS 桥的 TCP / TLS 复用连接迟迟不返回时，只有只读查询允许最多一次原路径备用请求。保留原连接的完整响应期限，先完成的有效响应生效；失败或未使用的连接释放，不换 DNS 上游、不直连回退、不放宽证书校验。
- 新连接、更新、区域传输、畸形响应及短期限查询不主动增加备用请求。并发仍受桥接查询槽位限制，每个慢复用查询最多两条活动连接，空闲连接仍最多 16 条。
- 三内核管理、原生重载和私有测试共用就绪边界检查，启动任务已取消或超时不能提交为成功。失败恢复和持久状态保存失败后的清理使用独立的 30 秒时限。
- 不改变节点、协议、测试目标、现有接管方式、分流、数据库结构或依赖。

## 0.6.59 恢复模式与策略路由

- 当前内核意外退出后，恢复快照同时保存当前 TUN / TPROXY 模式；恢复再次中断时不沿用上一次切换前的模式，成功后清除待切换状态。
- 非 TUN 模式每 30 秒核对私有策略路由，缺失时只补回 NaiLink 的精确条目，不重启正常内核；存在同表号或优先级的外来规则时停止修改，沿用原有安全恢复流程。
- 启动、网络资源、恢复快照等错误使用具体中文提示。未知错误仅显示受限诊断码，不误报为协议兼容性问题，也不回显底层路径或完整链接。
- 保留节点、订阅、群组、DNS、分流和未应用配置；不新增依赖，不修改协议和测试口径。

## 0.6.57 连接与生效核验

- 保留 Clash 订阅中仅针对节点服务器的 HTTPS DNS 策略；只匹配实际节点域名，不导入机场的网站分流或覆盖现有 DNS。更新订阅时保存提示，应用配置时交给当前内核运行；未更新的订阅仍沿用原有解析。
- 三个内核共用手动 HTTP 测量，保留首连耗时；确认同一连接复用后，详情提供第二次请求耗时。Mihomo 启用多入口 TCP 并发，自动测试启用统一延迟。
- 加入群组核验节点 ID 与保存结果；“查看生效出口”读取已应用的候选节点及原生内核当前选择，避免把加入或未应用更改当成正在使用。
- 新增一个可向后兼容的订阅 DNS 信息列，保留节点链接、ID、群组、路由、现有 DNS 和当前内核。不新增依赖，解析桥接、连接池与测试并发有上限，退出或失败时释放。

## 0.6.50 更新流程加固

- 同一文件的各下载入口、工具和地址族共用传输时限，避免重试叠加；官方 API 成功后优先复用，失败仍可尝试发布网站。
- 在线安装准备最多 15 分钟，超时在停服前退出，为 20 分钟后台任务中的安装及恢复留出时间。
- APK 先用本机已安装或缓存的依赖做只读模拟；齐全时不刷新固件软件源，安装也不再联网取依赖。确实缺依赖才走原固件软件源，失败仍在停服前退出。
- 分开提示固件软件源、依赖预检及准备超时；手动升级后不再把已达到目标版本的历史失败当作当前失败，旧版本检查记录打开时自动刷新。
- 原有节点、订阅、群组、未应用配置及当前内核保持，不新增依赖或数据库迁移。

## 0.6.49 在线更新下载恢复

- 下载中断时有限重试并尝试 IPv4，发布网站不可用时尝试固定版本的 GitHub 官方 API 文件入口；目标与校验和不变，不使用第三方镜像。
- 大 IPK/APK 传输期限从 3 分钟延至 10 分钟；在线任务仍有总期限。新包、回退包下载与校验失败均在停服前退出。
- 细分 DNS、TLS/证书、超时、连接中断、HTTP/限流、文件缺失与异常内容；只返回固定代码，不向页面暴露下载 URL 或签名参数。
- 下载通过临时文件完成后替换，失败不覆盖已有目标文件。0.6.38 等旧更新器需先通过[备用脚本](https://slobys.github.io/NaiLink/troubleshooting.html#download)升级一次。

## 0.6.44 mihomo DNS 连接稳定性

- TCP / DoT 连接按上游和出口隔离复用，最多保留 16 条空闲流连接，同一上游 / 出口最多 2 条，30 秒空闲释放。
- DoH 按出口复用 HTTP/2 客户端，限制连接数和空闲时间；保持证书校验、原 DNS 上游与分流。
- 最多 32 个查询同时发往上游，另允许 32 个短时等待；排队与交换共享原 6 秒期限，过载日志限频并仅记录固定代码。
- 失效复用连接只在只读查询中按原路径重建一次；取消或停服关闭活动、空闲连接与排队请求。无新依赖或数据库迁移。
- 私有节点测试遇到确认的监听端口冲突时清理后有限重试，不再把这类启动问题当成节点超时；其他错误与取消不重试。

## 0.6.43 手动测试与故障分类

- dae、sing-box、mihomo 普通节点手动 HTTP 测试统一最多 8 秒，包含新建连接和协议握手的真实耗时；多数节点提前返回，仍最多 8 个请求并行，停止即取消。
- 不改变后台自动健康检查、自动选路策略、节点认证、测试目标或用户 DNS / 分流设置。
- 修复 mihomo 私有节点哈希名未关联诊断的问题；只接纳本批已知别名，区分节点 TCP 连接超时、TLS 握手超时、WebSocket 握手失败和入口网关错误，不输出原始日志或凭据。
- 超时本身不能区分本地线路、服务端防火墙与服务端停机；网关 502/503/504 也不是密码错误。原参数经独立内核同样失败时，不自动改写节点或关闭证书验证。

## 0.6.42 Clash 订阅与更新保护

- 先识别格式，再解析 Clash YAML / JSON 的 `proxies`、SIP008、普通或 Base64 节点列表，避免把配置中的 HTTPS 地址误当节点。
- 兼容常见 SS / SS2022、SSR、VMess AEAD、VLESS / REALITY、Trojan、HY2、TUIC v5、AnyTLS、SOCKS5、HTTP(S) 参数；WS 新旧字段、证书校验和认证信息按值保留。实际运行仍受当前内核支持范围限制。
- 不导入 DNS、路由、监听或控制接口，不读取本地文件、不跟随 `proxy-providers` 外部引用。SSH、WireGuard、Snell 等尚未映射的 Clash 类型请使用现有分享链接 / 原生节点导入方式，未知参数明确报错。
- 任何节点转换或保存失败，整份订阅不替换；相同链接保留节点 ID、顺序与引用。手动加入群组的旧节点仍保留。错误显示安全的中文原因，不回传密码或订阅地址。
- 复用已固定的 yaml.v3 3.0.1；限制 4 MiB、4096 节点及 YAML 引用复杂度，无数据库迁移。

## 0.6.40 三内核管理

- 面板可切换 dae、sing-box、mihomo；Mihomo 1.19.33 按需安装，限 x86_64 / ARM64，不选用时不运行。
- 沿用节点、订阅和运行配置；切换前检查实际配置、DNS 与连接，失败尝试恢复原可用内核，不应用尚未保存的编辑。
- 保留现有 DNS 请求策略和传输路径，使用私有 DNS 桥接；代理 DNS 失败不静默直连。自动 WAN 下测试进程使用真实出口，避免被活动 TUN 再次接管。
- 协议与高级参数以兼容性报告为准，仅从 Clash YAML / JSON 提取内嵌节点，不应用完整配置。[完整范围与限制](../docs/core-switching.md)。

## 0.6.39 扩展协议包

- 在“代理内核”窗口按需安装，限 x86_64 / ARM64。下载约 30 MiB，预留 400 MiB 安装空间；不使用时不启动 Tor。
- Naive HTTPS 使用 Cronet，默认 8 MiB 接收窗口；WireGuard 使用用户态 endpoint，默认 1 个工作线程。
- Tor 仅支持 TCP，每个运行配置最多 1 个，首次引导可能较慢；复用私有缓存，程序崩溃或切换后清理子进程。
- 校验完整包、版本、架构及私有依赖后才替换组件指针；下载失败保留旧组件和全部配置。
- ARMv7 / MIPS 不提供扩展包，也不改变既有透明代理限制。[协议格式与限制](../docs/core-switching.md)。

## 0.6.38 批量测试与原生协议

- 路由模式使用有界后台任务，一次提交整批节点并增量返回结果；停止保留已完成项，可继续剩余项。短暂请求失败重试不会重复启动任务。
- sing-box 整批共享一个私有测试进程，最多 8 个并行 HTTP 请求；排队与进程启动不计入节点延迟，HTTP 超时与 dae 统一为 3 秒。不扣减真实连接和握手耗时。
- 原生配置错误按节点隔离，不拖累整批。切换内核会取消旧任务，防止旧结果混入新内核；临时进程不接管 TUN，不改用户配置。
- 增加 Hysteria 1、SSH、Snell 4/6 URI，以及 sing-box 单出站 / 封闭出站组合 JSON，支持 ShadowTLS 组合。原生节点提供 JSON 编辑；切回 dae 前会明确指出不兼容节点。
- 导入窗口显示当前内核协议、链接格式和组件限制。0.6.39 可按需安装 Naive/Cronet、WireGuard 与私有 Tor 扩展包；SSR、Juicity 不由 sing-box 实现。
- 无数据库迁移和新依赖；普通 Linux/Docker 保留原测试接口。

## 0.6.37 节点延迟对比修复

- 手动测试不再被后台自动检测覆盖；自动检测单独标注，保留各自的真实结果和时间。
- sing-box 手动测试与 dae 共用目标解析缓存，遵循配置中的 HTTP 方法，竞速可用的 IPv4 / IPv6 目标，并核对 `generate_` 响应码。
- 手动值包含新建连接和协议握手，不是 Ping；私有测试进程启动不计入，不扣除连接成本。测试结束取消未完成的另一地址族请求。
- 不修改节点、订阅、群组、分流和现用内核，不改变后台选路的健康检测。

## 0.6.36 sing-box 节点测试修复

## 0.6.35 节点参数与 Reality 兼容

- 处理常见链接的 `headerType=none`、`udp` 和 `spx`；逐节点收集中文错误，参数只显示名称，不泄露密码或链接。

## 0.6.34 统一内核管理与切换

- 默认继续使用 dae。面板顶部“内核”提供安装 sing-box → 检查兼容性 → 切换；只安装所需的可选内核，现有安装方式不变。
- 首版仅为已满足 NaiLink 安装条件的 x86_64 / ARM64 固件增加切换，不开放 ARMv7 / MIPS 的 sing-box，也不绕过原有 dae 安装能力检查。需要工作正常的 nftables / fw4、TUN 与额外 180 MiB 可用存储，建议 1 GiB 以上内存。
- 从官方固定版本 OpenWrt 包中只取静态内核程序，校验 SHA256、架构和版本；不运行其安装脚本、不覆盖 NaiLink 配置。
- 配置、就绪、日志、HTTP/UDP 节点测试与流量统计统一适配；切换不会改写数据库或应用待生效编辑。不兼容的协议参数、复杂规则、多个 WAN、固定群组多节点等会阻止切换，自动策略差异在报告中说明。
- 切换失败恢复旧内核；中断后恢复私有事务快照；意外退出最多在 5 分钟内尝试两次重启。无法证明资源已清理时停止自动切换并保留诊断信息，不同时运行两套接管。
- 修复 dae 旧监听循环在重载后抢读首个新连接/DNS 请求的问题。详见[内核使用说明](../docs/core-switching.md)和[验证边界](VALIDATION.md)。

## 0.6.33 更新失败与规则库恢复

- 安装失败或新管理 HTTP 未就绪时，尝试用原生包管理器恢复旧包及已校验的配置/数据库快照，保留失败现场的额外备份。保持原启停和自启选择；回退也失败时停止服务并明确报告，不伪装成功。自定义外部数据库链接需自行备份和手动升级，不自动覆盖。

- 当时未集成其他内核；0.6.34 的落地范围见上方说明，后续方向见[多内核规划](../docs/multi-core-plan.md)。

## 0.6.30 升级后的 DNS 与分流恢复

- 恢复 DNS 缓存时，等域名路由关联写入完成再报告就绪，避免异步队列积压使浏览器缓存 IP 暂时缺少分流关联。
- 正常停止时在 `/var/run/daed` 保存最多 1024 条、2 MiB 的有效地址记录；相同配置重新启动且快照不超过 10 分钟时恢复。保留原 TTL，按当前规则重建路由，不保存节点密码，不写入永久配置。
- 安装器分别检查管理 HTTP、代理监听、DNS 上游初始化和缓存路由恢复。网络仍在恢复时提示原因并保留新服务运行，不把页面可访问当作所有网站可用。
- `nailink --check-network` 提供只读诊断：恢复状态、群组策略、双栈候选节点和 Google / ChatGPT 的 DNS、TCP、TLS 观察。候选节点不等于网站实际看到的公网 IP，HTTP 403 也不等于连接失败。
- 保留现有节点、订阅、自动选路与 DNS 设置。旧版从未保存过快照，所以第一次从 0.6.29 或更早版本升级无法恢复旧进程没有导出的缓存；后续正常停止、重启和升级才可使用快照。断电清除 `/var/run`，崩溃未保存新快照时也不能保证恢复。

## 0.6.29 协议编辑与 UDP 诊断

- SS 编辑支持三种 SS2022 加密，按 SIP002 生成明文百分号编码的 SS2022 分享链接；普通 AEAD 继续使用 Base64URL，IPv6 地址只加一层方括号。
- 编辑 SS、HY2、AnyTLS、VLESS 等标准 URI 时保留未改动和未展示的查询参数，以及重复参数；VMess JSON 保留扩展字段。修改已知参数时替换其旧别名，关闭 SS 插件时清理插件参数。保留参数不代表内核支持所有扩展；SSR 和标准 VMess URI 转换不在完整扩展保留范围内。
- Trojan、TUIC、Juicity 编辑正确读取内核已支持的证书校验别名，HY2 端口别名优先级与内核一致。VLESS 不再显示当前内核不会执行的节点级跳过证书验证开关。
- 在手动节点和订阅节点的详情中增加可选“UDP 连通性”检查，向配置的 `udp_check_dns` 目标发出 DNS UDP 请求，结果与网页延迟分开；不轮询、不修改健康历史、选中节点和数据库结构。
- 修复 SS 与 VMess TCP 流关闭等待加密读取锁的问题，关闭时先中断 I/O，并发关闭仅执行一次；不改变正常连接的期限，UDP 包接口保持不变。
- 独立 sing-box 与官方 Juicity 服务端回归覆盖 SS/SS2022、VMess、VLESS、Trojan、HY2、TUIC v5、AnyTLS、Juicity，检查 HTTP 负载、连接复用、分段响应、关闭后重连、UDP 和证书拒绝。受控测试不能替代实际公网线路和断网场景的长期验证。

## 0.6.28 DNS 查询隔离与连接诊断

- 多个启动 DNS 解析器之间分配剩余时间，避免第一个无响应耗尽请求期限；显式指定单个解析器时保留原有期限。
- DoQ 为单个查询设置期限和取消处理，发送完整查询后关闭发送方向；取消只影响当前流，其他查询继续复用 QUIC 连接。
- HTTP/3 DNS 与 DoQ 明确接管底层 UDP 套接字，握手失败、主动关闭及连接结束时释放，重复关闭只清理一次。
- TCP/DoT DNS 查询取消后隔离迟到响应的 ID，其他在途查询可继续；排队取消不碰共享套接字，部分写入造成帧不完整时仍回收连接，空闲时清理未完成查询的残留状态。
- 增加启动解析、DNS 转发、路由选择和代理建连的 Debug 诊断，记录阶段、耗时、尝试次数和固定结果分类；DNS 失败警告增加阶段与耗时，不额外记录凭据或完整链接。
- 保留现有节点、订阅、群组、DNS、路由和证书校验，无数据库迁移、新增依赖或代理协议行为变更。目标设备长期稳定性仍需实际线路验证。

## 0.6.27 DNS 连接与取消恢复

- 修复 DoH 请求、DoT 握手及 TCP DNS 写入未正确受请求期限或取消控制的问题，避免上游无响应时长期拖住解析。
- 同一 DNS 转发器的冷启动连接创建串行合并，已有连接继续并行处理查询；连接池关闭后拒绝晚到连接，防止重载后重新留下旧资源。
- UDP DNS 取消时及时中断读取，取消回调结束后才回收连接。正常取消不再累计节点失败次数；DoH 不再修改调用方共享的查询数据。
- TCP 拨号即使在单次尝试到期后返回成功，也会关闭晚到连接，按原有条件尝试同群组备用节点。固定选择、单节点和应用数据不重放的约束保持不变。
- 保留节点、配置、分流和证书校验，不新增依赖。主要修复已重现的等待与清理问题，不承诺每条公网线路或网站均恢复。

## 0.6.25 首次连接恢复

- `tcp+udp` DNS 上游的 UDP 尝试最长 1.5 秒，较短请求会为 TCP 留出一半时间；纯 UDP/TCP 上游和已有分流规则不改。
- 自动群组存在另一可选代理节点时，TCP 首次建连失败可在同一群组内补试一次。两次共享最多 8 秒，首次为备用保留一半预算；固定策略、单节点群组与直连不自动换节点。
- 仅在应用数据开始转发前处理超时、拒绝、复位和 EOF；不重放请求，不因单个目标失败强制拉黑节点，只通知现有健康检查。取消后及时关闭晚到的连接，取消不触发额外回退。
- 不新增依赖，不迁移数据库，不强制关闭 IPv6/QUIC，不改用户节点、DNS、路由或选择策略。已有配置可直接升级。
- 回归覆盖本地无响应 UDP → 真实 TCP DNS、备用节点预算、固定选择、取消、应用负载，以及 VLESS TLS/TCP、TLS/WebSocket 的独立服务端互通。用户线路的 YouTube 间歇性故障仍需升级后实际复测。

## 规则库路径修复

- `/usr/share/daed/geosite.dat` → `../v2ray/geosite.dat`
- `/usr/share/daed/geoip.dat` → `../v2ray/geoip.dat`

可读性；只读预检在规则缺失时提示警告，允许首次安装补齐固件依赖。

## 订阅通过本机 PassWall 出口下载

0.3.1 默认使用自动模式：先尝试原来的系统路径与 dae 路由；失败后，读取已运行
PassWall 的本机 SOCKS 出口再尝试下载。端口每次动态读取，不固定为 1070，
仅接受回环地址。下载域名交给 SOCKS 出口解析，继续校验 HTTPS 证书。
新增订阅、手动更新和定时更新使用相同逻辑，不修改订阅链接、节点或数据库结构。

升级后无需额外设置；原配置缺少 `subscription_proxy` 时也按 `auto` 处理。
对于“系统路径 AUTH_FAIL、PassWall SOCKS 成功”的订阅，添加/更新时保持
PassWall 正常运行。它借用现有可用出口，无法使未获服务商授权的出口自动获得权限。
没有 PassWall 时，原有可用下载路径仍正常使用；下载失败不会删除已有节点。

可选的全局下载策略（立即对后续下载生效，无需重启）：

```sh
# auto：系统路径、dae 路由失败后尝试 PassWall（默认）
# passwall：仅用 PassWall SOCKS，失败时不切换出口
# off：只使用原有系统路径和 dae 路由
uci set daed.main.subscription_proxy='auto'
uci commit daed
```

不会启动、停止或修改 PassWall，也不会接管其他应用的下载。错误只报告状态和
已知 `AUTH_FAIL` 代码，不输出订阅 URL、服务商响应正文或 cookie。

## 订阅下载诊断

出现 403 时，先确认订阅在其他客户端的本次更新是否成功，区分已有节点可用
与订阅可下载。Daed 报错中的 `route` 是 dae 路由下载，不代表使用 PassWall。

仓库提供独立的只读工具 `openwrt/subscription-check.sh`，可用 `sh` 执行。
它读取最多 3 条 PassWall 订阅，分别测试系统路径的 Daed 请求头、PassWall
请求头/会话，以及可用的本机 PassWall SOCKS 出口；也可传一个命名订阅 section ID。
系统路径仍可能受透明代理规则影响，curl 测试不等同于 Daed 的 Go 下载客户端。

输出仅含 section ID、URL 的 SHA-256 指纹、HTTP 状态、curl 返回码、已知鉴权
错误代码及内容格式/节点链接数。节点链接数不证明协议参数可导入；HTML、Clash
YAML 和鉴权响应会单独标识。临时响应和 cookie 使用私有目录，结束后清理。
该工具不新增依赖，不修改订阅、服务、路由或防火墙配置，不关闭 TLS 校验。

只有系统路径失败、本机 SOCKS 成功时，才进一步核对两条下载路径的出口与权限。
`AUTH_FAIL` 表示订阅服务拒绝鉴权，需要结合服务商错误说明处理，不能仅靠状态码
认定是 User-Agent 问题。

## 已启动但无法访问的只读诊断

`openwrt/network-check.sh` 收集实际 LAN/WAN 设备、默认路由、现有 TC 过滤器、
代理服务状态、本机 DNS、国内/Google 的 IPv4 HTTPS 和 Google IPv6 HTTPS，
并在探测前后分别读取服务状态和已遮盖凭据的日志。不修改 UCI、数据库、路由、
防火墙或服务，不安装缺少的工具；DNS/HTTPS 请求有时限，仍经过当前透明代理路径。

v2 将 procd 未报告实例标为 `unreported`，查询失败标为 `unavailable`，不据此
判断代理已停止；额外报告常见代理核心进程是否存在及 nftables/iptables 中的
PassWall/OpenClash 文本标记数量，不输出进程参数或防火墙规则内容。这些标记
可能残留，核心也可能由不同插件使用，因此 `traffic_owner` 始终为 `unknown`。
HTTPS 成功只能说明当前路径可用，使用 PassWall 时的成功不代表 Daed 转发成功。

历史日志在探测前单独显示。探测后按两次日志快照的重叠部分识别新增行；日志
轮转或重置后无法确认连续性时标为 `log_continuity=unknown`，不将历史行冒充
本次探测日志。新增日志也可能来自后台流量，不能单独证明探测经过 Daed。
排查 Daed 时需在明确停止其他代理、从面板启用 Daed 后采集；测试结束若仍不通，
先在面板停止 Daed，再恢复原有代理，不要让两套透明代理同时接管网络。

`Ready`、群组选择节点和 eBPF 加载成功不能单独证明代理出口可用。启动时空
配置的 `[direct]` 不代表重载后的最终路由。Netkit 回退 veth 后继续成功启动时，
应先核对真实绑定和实际连接结果，避免仅根据该回退提示更换 iproute2。

## 兼容性与架构范围

| 程序架构        | 固件包标签                                                       | 状态与基线                                 |
| --------------- | ---------------------------------------------------------------- | ------------------------------------------ |
| x86_64          | `x86_64`                                                         | 保留原支持，amd64 v1                       |
| ARM64           | `aarch64`、`aarch64_generic`、Cortex-A35/A53/A55/A72/A73/A75/A76 | 保留原支持，ARMv8.0                        |
| ARMv7 小端      | Cortex-A5/A7/A8/A9/A15，具体标签见 `sdk-matrix.json`             | 实验构建；已测常见内核无法加载透明代理回调 |
| MIPS32r2 大端   | `mips_24kc`、`mips_74kc`                                         | 实验构建；已测常见内核无法加载透明代理回调 |
| MIPSel32r2 小端 | `mipsel_24kc`、`mipsel_74kc`                                     | 实验构建；已测常见内核无法加载透明代理回调 |

ARMv5/v6、32 位 x86、MIPS64、RISC-V 及矩阵之外的固件 ABI 暂不提供安装包。
脚本结合 `uname -m` 与包管理器的有效架构选择运行包、对应字节序的 BTF 解析器；不会只用 `mips` 这一名称判断大小端，也不会强制安装其他 ABI 的包。

**32 位版本仅保留实验构建，当前不推荐用于透明代理。** 上轮交叉构建和 API/数据库检查通过，但本轮完整系统 QEMU 已证实 OpenWrt 24.10.4 / Linux 6.6.110 的 ARMv7、MIPS 大端/小端均无法加载当前核心需要的 `bpf_loop` 回调；Debian 6.1 的完整核心加载另有回调/数据包对齐拒绝。安装器增加实际内核探针，在替换程序前拒绝这些内核。DNS 模块测试通过不能替代透明 DNS 截获验证。[固定 eBPF 依赖未承诺支持 32 位平台](https://github.com/cilium/ebpf/blob/v0.20.0/README.md#requirements)。不自动升级内核、修改 JIT 设置或强行绕过校验；自定义内核通过最小探针后仍需完整代理验证。

其他环境要求：

- 固件提供现代 JavaScript LuCI、uhttpd CGI、rpcd、UCI、jshn 和 jsonfilter。
- Linux 5.17+，具备 dae 所需 BPF 功能。支持原生 BTF 或加载器固定搜索路径中
  对应当前内核的外部 BTF/vmlinux，随包解析器核验格式、ELF 架构和网络类型。
- 固件自身软件源能够提供匹配本机内核 ABI 的 `kmod-sched-core`、
  `kmod-sched-bpf`、`kmod-veth` 及 `ca-bundle`、`v2ray-geoip`、`v2ray-geosite`。
- 足够的临时下载空间和 overlay 存储。APK 格式要求 apk-tools 3.x。

  0.6.22 的运行程序本体约 52–57 MiB，另需规则库、依赖、下载及升级备份空间。常见 16/32 MiB 闪存设备不能仅凭 CPU 匹配直接安装；需要用户自行提供足够的可写存储，脚本不自动扩容或配置 extroot。

安装器不刷固件、不替换 BTF、不修改其他代理、DNS 或防火墙。
ARM64 架构标签以 `sdk-matrix.json` 为准，程序使用 ARMv8 基线。APK 按
`/etc/apk/arch` 选择标签，仅在列表缺失或为空时退回编译默认值。
矩阵包含部分社区固件标签；安装仍要求本机包管理器接受该标签，且固件自身能提供匹配的依赖。
系统名称、BTF 检查或管理页面启动不构成实际代理兼容性证明。

## 登录集成

CGI 网关通过 rpcd 校验当前 LuCI 会话对 `luci-app-daed-router` 的管理权限，
每个请求均重新校验，退出或过期的会话不能继续调用管理 API。
会话交接使用同源 POST，cookie 设置 HttpOnly / SameSite=Strict，并在 HTTPS 下
设置 Secure。写请求检查 Origin；不在 URL、页面或浏览器存储中下发 Daed JWT。

网关复用 wing 现有 SQLite 和 JWT 库生成短时本地授权，保持 wing 子模块固定提交，
不新增 npm 或 Go 依赖。私有服务凭据保存在 `/etc/daed/luci-session.json`，权限
0600。首次启动前准备身份，之后 CGI 不直接读写数据库。
只读 LuCI 账户可看日志，管理面板需要该 ACL 组的写权限。

## 开发

```sh
# 在已有工作区依赖构建后，生成路由器专用前端
pnpm --dir apps/web build:openwrt
# 应用主仓库中可审查的订阅下载补丁；子模块提交不变
python3 openwrt/prepare-wing.py wing
# 使用独立输出目录，避免工作区测试/普通网页版构建覆盖路由器前端
python3 openwrt/runtime.py --cpu x86_64 --wing wing --web apps/web/dist-openwrt --version 0.6.29 --work /path/to/sdk-cache --output /path/to/runtime
python3 openwrt/build.py --target ipk-x86_64 --binary /path/to/runtime/daed --btf-probe /path/to/runtime/btf-probe --luci-proxy /path/to/runtime/luci-proxy --version 0.6.29 --work /path/to/sdk-cache --output /path/to/packages
# 全部 SDK 目标构建完成后再生成完整发行清单
python3 openwrt/manifest.py /path/to/packages --version 0.6.29
node --test tests/openwrt/ui.test.cjs
```

路由器后端增量源码位于 `openwrt/wing/`，准备工具核对固定上游源文件哈希，
拒绝覆盖未知修改，并支持重复执行。源码归档同时包含这些文件与原始子模块；
构建前执行上述准备命令即可复现，不依赖未推送的子模块提交。

`--cpu` 可选 `x86_64`、`arm64`、`armv7`、`mips`、`mipsle`；各有 `ipk-` / `apk-` SDK 目标。MIPS 必须使用上述构建器准备 CGO 静态 SQLite，不能直接套用 `CGO_ENABLED=0`，否则会生成启动即失败的数据库占位驱动。SDK URL、哈希和
feed 提交固定在 `sdk-matrix.json`，原生打包后逐一验证文件、架构和权限。
手动运行 **OpenWrt plugin** 工作流，版本号必须与源码、安装器和在线文档一致，默认只生成 artifact。
在 `main` 勾选 `publish` 后，所有测试、内核探针和 SDK 打包通过才创建测试版草稿；上传前再次核对 SHA-256、完整架构清单和源码提交。
同名已发布版本及指向其他提交的标签不会被覆盖，同一提交的草稿允许重试。维护者核验草稿后发布，不需要创建发布 PR 或原项目组织权限。

自动测试、原生 uhttpd / rpcd 和浏览器验证的范围见 [VALIDATION.md](./VALIDATION.md)。

运行概况维护回归（Linux，已初始化固定子模块并具备 Go/Clang 构建环境）：

```sh
python3 openwrt/prepare-wing.py wing
(cd wing && go test -count=1 -v -tags daed_runtime_test ./dae ./graphql/service/general)
(cd wing/dae-core && go test -count=1 ./control -run 'Runtime|RelayTCP|Tracked|ActiveTCP')
```

`daed_runtime_test` 仅用于测试，正式构建不启用该标签。

协议互通回归（仅本地回环，测试工具不随插件安装）：

```sh
# 独立 sing-box 1.14.3；可选提供官方 juicity-server 0.5.0
sudo python3 tests/openwrt/protocol_interop.py --wing wing --sing-box /path/to/sing-box --juicity-server /path/to/juicity-server
```

测试使用临时认证和证书，检查真实 HTTP/UDP、连接复用、分段响应与关闭后重连；运行需要允许测试套接字使用 SO_MARK。
`tests/openwrt/browser-protocols.cjs` 配合隔离原生 LuCI 面板检查实际协议编辑和 UDP 诊断。独立服务端版本及下载哈希固定在 OpenWrt 工作流中。
